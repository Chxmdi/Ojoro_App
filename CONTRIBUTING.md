# Contributing to Ojoro

## Branching

Create short-lived branches from `main`:

- `feat/<issue>-<slug>`
- `fix/<issue>-<slug>`
- `chore/<issue>-<slug>`

## Pull requests

Every PR should:

1. link a GitHub issue;
2. explain the user/system outcome;
3. include test evidence;
4. describe rollout and rollback;
5. call out privacy, location, youth, safety, payment or AI-risk implications.

## Recommended merge policy

- PR required before merge
- minimum 1 approval
- CODEOWNERS review for protected paths
- required status checks
- dismiss stale approvals
- require conversation resolution
- block force pushes and branch deletion
- squash merge preferred
