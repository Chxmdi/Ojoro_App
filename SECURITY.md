# Security Policy

Do **not** report security or privacy vulnerabilities in public GitHub issues.

Use GitHub Private Vulnerability Reporting / Security Advisories for:
- authentication or authorization bypass
- account takeover
- exposed secrets
- precise-location or presence leaks
- youth/minor safety exposure
- payment vulnerabilities
- moderation bypasses
- sensitive data disclosure
- challenge mechanics that can create material safety risk

## Severity

- **P0** — immediate incident response; blocks all affected releases.
- **P1** — blocks the affected release until mitigated or explicitly risk-accepted.
- **P2** — important but recoverable degradation.
- **P3** — low-risk defect or hardening item.

Security fixes should include regression coverage whenever feasible.
