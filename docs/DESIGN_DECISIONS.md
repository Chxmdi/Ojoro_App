# Build decisions

Decisions made while porting the design handoff, where the handoff was silent,
inconsistent, or couldn't be matched exactly. Each one names what we chose and
why, so it can be reviewed and reversed. Newest at the bottom of each section.

## Platform and tooling

| Decision | Why |
|---|---|
| Backend is Supabase | See `docs/adr/0001-backend-supabase.md`. |
| TypeScript pinned to 6.0.x | typescript-eslint supports TS < 6.1; TS 7 broke lint. Dependabot ignores TS ≥ 6.1 until typescript-eslint supports 7. |
| NativeWind 5.0.0-rc.0 | The handoff requires v5; rc is the newest v5 release. Upgrade to 5.0.0 stable when it ships. |
| Local Supabase enables a fake Twilio provider | Supabase Auth refuses phone sign-in with no SMS provider, even for test numbers. The fake credentials can't send anything; hosted projects ignore `config.toml`. |
| No hosted Supabase project yet | Creating one failed: a BMF member account is at the free plan's 2-active-project limit. We don't pause, delete or reuse other projects (`ojoro-festival-2027` is a different product). The owner frees a slot or upgrades the plan, then we create `ojoro` in `ca-central-1` (the sample content is in Montreal). |

## Design system

| Decision | Why |
|---|---|
| Added `title-sm`, `label-sm`, `overline` text styles | The web reference uses them and `tokens.json` doesn't list them (DESIGN_SYSTEM_PORT §1). |
| Added `home`, `compete`, `person` icons | Drawn inline in the tab bar of the screen designs; moved into `Icon` on the same grid. |
| `Text` has a `tone` prop | Lets labels on signal/inverse grounds take `on-signal`/`on-inverse` without fighting the default colour. |
| Switch knob follows the intent, not the CSS | The web `.sw` CSS swaps its paddings, clipping OFF (visible in HostRequests/HostSeries PNGs). The knob sits 3px in and the word 10px from the edge. |
| Switch, Toast: `mark-ring` when the fill merges with the ground | On `confirmed`, `inverse` (black) on `surface` (oxblood) is 1.09:1. The design rule for oxblood/black adjacency applies: a 2px white `mark-ring`. No token changed. |
| Error toast has no heavier rule | Neither the web reference nor the States design draws one on the toast. The error is carried by the alert icon (labelled "Error") and the words. The heavier rule appears on inline errors (Input). |
| Toast action isn't `TextButton` | `TextButton` is muted text; on the inverse strip it would vanish. The web styles `.oj-toast-action` separately too. |
| Modal: tapping the scrim does nothing | Modals are for irreversible or costly choices; they need an explicit answer. Sheets do close on scrim tap. |
| Button labels wrap; Chip labels don't | Display labels must never truncate. Chips sit in horizontal scrollers. |

## Slice 01 backend

| Decision | Why |
|---|---|
| Friends and Crews mean "people you have played with" for now | Privacy settings offer Friends and My Crews, plans and Down For have a friends audience, but neither Friends (M1) nor Crews (M2) exist yet. Played-together (both checked in to the same game, so both have the Passport stamp) is the closest real relationship. Replace `authz.connected()` when they land. |
| Levels are self-only | "Levels are only used to match you fairly. They never show as a score." `profile_sports()` returns the level to the owner only; others see sport, position and main sport. |
| A Down For match makes you a member | Main says "Ojoro matched 6 of them into a plan" and Plan says "You're down, but it's not on yet": a Down For is an advance, conditional I'M DOWN. Matched people join with `via = 'down_for'` and can leave. Run It Back, by contrast, only invites (PRD §9.8). |
| Down For matching rules | PRD §9.2 only says signals "can" be matched. Rules in docs/SLICE01_CONTRACT.md §Down For matching: join the fullest compatible forming plan, else group signals (oldest first, shared start time, mutual radius, no blocks, everyone's minimum met), else stay active. |
| "Same intent" = same person, sport and overlapping window | PRD requires idempotent creation without duplicate active signals; an exclusion constraint enforces it and a repeat returns the existing signal. |
| Plans lock at capacity, then join the waitlist | "The plan locks at 8"; States shows "Couldn't join… WAITLIST". `im_down` on a locked plan returns `plan_full` and the app offers `join_waitlist`. |
| Waitlist auto-promotion stops when check-in opens | States: "If a spot opens before 7:00 you're in automatically" (7:00 = check-in opening for a 7:30 game). |
| Check-in opens 30 min before the start and closes at the end; 150 m from the meeting point | Activity: "Opens at 7:00 when you're within 150 m" for a 7:30 game. The meeting point coordinates are used when set (parks are larger than 150 m), else the place centroid. |
| After stays open 24 h; location sharing ends at the game's end + 30 min | After: "OPEN UNTIL WED 9 PM" for a Tue game ending 9:00; CheckIn: sharing "until 9:30" for a game ending 9:00. |
| Participant Confirmed threshold = half of the players, rounded up, at least 2 | After: "3 of 8 confirmed. At 4 it becomes Participant confirmed." PRD §11.3: "multiple participants confirm". Players = people who checked in. |
| Recap without a result | When After closes with no verified result, the Recap is still created (attendance, minutes) with the unverified score marked `self_recorded`, or no score. A recap is a permanent object (§9.8). |
| The Run It Back caller is not a member either | "Nobody is in until they tap I'M DOWN." The caller hosts the new plan but taps I'M DOWN like everyone else. Two players running it back to the same time get the same plan. |
| Pull-in permission | Allowed for people you've played with, or people with Pull Me In `nearby` for the sport. Quota 3 per plan per inviter (NeedOneMore: "You can send 3 more invites") plus 20 a day. Refusals don't say why (blocks stay private). |
| "first game" shows to fellow members whatever the history setting | Plan shows "New to the area · first game". It says the person has no history, which isn't history; gating it on `history_visibility` (default Friends) would hide it from exactly the people meeting them for the first time. |
| Games hosted is public (minus blocked) | Plan shows "Started the plan · 40 games hosted" to everyone in the plan. It's host reputation, not personal history. |
| Reputation: a table of endorsements, shown from 5 | You: "A signal only appears after 5 confirmations." `give_reputation` exists for After; no UI is designed for giving yet. |
| Sports catalog is a migration, places are seed | Sports are reference data every environment needs; places, people and plans are sample content. |
| Day parts: morning < 11:00, midday 11:00–16:59, evening ≥ 17:00 local | OnboardWhen has MORNING / MIDDAY / EVENING without boundaries. |
| STILL ON TONIGHT looks twice as far as your radius | States shows Parc Jarry at 4 km for a 3 km radius ("a bit further out", FirstHome). |
| Hosts can start and end a game early | CheckIn: "Ade starts the game once the teams are set"; Live: FULL TIME (host). Without the host, times decide. |
| Live score updates, chat, notifications and payments are out of the backend for now | Not in Slice 01 (PRD §18.3) or not decided (payments). Cost is stored for display only. |

### Auth, onboarding, You, profiles, report/block

| Decision | Why |
|---|---|
| The auth gate wraps every root screen by route name (Stack `screenLayout`) | Signed-in screens never mount while signed out or onboarding, so there's no flash of the wrong screen and new routes are protected without being listed. `(auth)` is signed-out only, `(onboarding)` is unfinished accounts only, `storybook` and `+not-found` are public, everything else needs a finished profile. Rules in `features/auth/gate.ts`. |
| Deep links survive sign-in, in memory | A signed-out (or onboarding) visit to any app route other than Home is remembered and opened when the gate lets the person through. Memory only: a cold restart mid-sign-in lands on Home. |
| Apple and Google buttons show only when the build says the provider is configured | `EXPO_PUBLIC_AUTH_APPLE=on`, `EXPO_PUBLIC_AUTH_GOOGLE=on`. Neither is configured locally (contract, "Not in Slice 01"). Without them USE A PHONE NUMBER is the primary button, so the one way in leads. On web they call `signInWithOAuth`; native needs `expo-apple-authentication` / a browser session (new dependencies: ask first). |

## Step 3 backend

Liquidity (PRD M4). Contract: `docs/LIQUIDITY_CONTRACT.md`.

| Decision | Why |
|---|---|
| Areas come from a list of neighbourhoods, not device location | New users never gave an area, so "near you" was empty. `areas_list()` derives neighbourhoods from public places (label "Plateau, Montréal", centroid rounded to 0.01°); `set_area()` stores that centroid. No permission prompt, never finer than 0.01°. An area with no place can't be picked yet. |
| Latent demand: k = 3 | PRD §9.6 asks for aggregate demand; Discover/FirstHome show counts only. Three is the smallest group where a count doesn't point at one or two people, and FirstHome's own sample is 3 runners. Below 3 the bucket isn't returned at all (not even as "a few"). Residual risk: someone moving their radius can see a count change by one; radii are 1–50 km and points 0.01°, so it locates nobody. |
| Buckets are sport × part of day (morning/midday/evening, local) | "after 7", "this week", "an evening run". The suggested start is the time most of them can make (15-minute boundary, about an hour out, as Down For matching). The count is people who can make that start, not everyone in the bucket. |
| A bucket with an open plan you could join isn't latent demand | Then the answer is the plan (Ojoro Now / plans_nearby), not "nothing on". |
| Latent demand exists mostly because of min_participants | Two compatible signals already form a plan at once (Slice 01 matching). Unmatched demand is people whose minimum the group can't meet yet, people whose radii don't overlap each other but both reach you, or audience rules. The seed uses minimums ("each needs 4", "each needs 6"), which is what "Add yourself and it becomes a plan at 4" means. |
| Create From Demand = a Down For plus the existing matching | Consistent with "A Down For match makes you a member": the caller's signal is matched with the same `private.match_signal`, so the caller hosts and everyone matched is a member via `down_for`. If an open plan appeared meanwhile it's joined instead of forming a duplicate. Nothing compatible → `demand_unavailable` and nothing is kept (no stray signal). |
| Create From Demand needs no minimum of 3 | The UI only offers it on a shown bucket; the server applies the same rules as `create_down_for`, which can already form a plan of 2. A separate gate would only make the two paths disagree. |
| Rate limit: 5 plans formed from signals per person per 24 h | Spam prevention (PRD §9.5 "rate limits are mandatory") without a new table: counted from `plans.created_by` with `source = 'down_for'`. |
| Argument names stay `p_sport_id` | The brief wrote `p_sport`; every Slice 01 RPC uses `p_sport_id`, and the screens already build args that way. |
| Ojoro Now = forming plans with spots + GAME ON games not started + live games, within your radius | PRD §9.6 "starting-soon activities, active places and plans forming". Live games are "watch" (spectating isn't built: open Activity). GAME ON games are "join" when join_waitlist would confirm you, else "waitlist". |
| Reasons are returned as facts and as English | The brief asks for plain-language reasons; the app may show `reason` or compose from the numeric columns. Facts only: time, distance, people you've played with, "needs one more". |
| Surprise Me: preference orders, it doesn't filter | Discover puts SURPRISE ME right under "nothing on for volleyball"; filtering to your sports left it empty most of the time. Safety (blocks, visibility), radius and level are hard constraints; your sports rank first, then demand in your sports, then other sports with the reason "it's something different from your usual". Deterministic order (main sport, people you've played with, soonest, nearest, id). |
| Skill fit = members' average level within 1.5 steps of yours | "Levels are only used to match you fairly." Levels are never returned; the only trace is "it's close to your level" and the absence of plans that aren't. |
| The Concierge is a parser plus the same ranking | Create: "rules-based stub first; the AI part is M9". Minutes, a sport (with a few aliases: soccer, run, hoops, sparring…) and "meet people" are read from the text; with minutes, only plans that fit and start in the next 6 hours. The text is never stored or logged. |
| People are searchable by name only by people who've played with them | No "find me by name" privacy setting exists, and the profile visibility settings cover sports/history/availability, not discoverability. Propose a `searchable_by` setting with Friends (M1). |
| People to move with: strangers only with Pull Me In `nearby` | Listing a stranger "near you" reveals they're within your radius. Pull Me In `nearby` is the only place someone said anyone nearby may reach them; they must also let you see their sports. Crews count is null (Crews don't exist). |
| Place counts only count plans you can see | Counting friends-only or invite-only plans would reveal that they exist. "Tonight" ends at 4 AM local. Cancelled and expired plans, and GAME ON games that were cancelled or finished, never count (the "20 TONIGHT" bug). |
| Low density = fewer than 2 joinable plans and games near you in 7 days | FirstHome is the honest state for "nothing (or almost nothing) to join". `home_density()` returns the counts so the headline can say exactly what's true; the threshold is one number (`LOW_DENSITY_THRESHOLD`) to tune with data. |
| A bit further out = beyond your radius, up to twice it, at most 25 km | Same "twice your radius" rule as STILL ON TONIGHT (Slice 01). |
| Need One More tiers: played together → friend of a friend → nearby | PRD §9.5 order is friends → Crew → previous participants → friends-of-friends → compatible nearby. Until Friends and Crews exist the first three are all "played together". Friends-of-friends and nearby people are only listed when Pull Me In `nearby` is on, because `pull_in()` refuses anyone else; the ranking never lists someone the invite would reject. Within a tier the Slice 01 order stays (Pull Me In for the sport, free then, games together), which matches the NeedOneMore sample. |
| Candidate distance in whole kilometres | NeedOneMore shows "2 km away". Distances between people are computed from two 0.01° points and rounded up to a whole km (at least 1), so they can't be used to place anyone. |
| Activity (Create) maps to create_plan | create_plan already takes capacity, teams, cost, kit, level, meeting point, attendance rule and duration. An Activity is a plan that becomes the Activity at GAME ON. "Repeats" has no backend (Rituals/Series are later); the screen shouldn't offer it yet. |

The quiet-area user Nneka (+1 555 555 0120) is a new test number; it works after the next `supabase start`. |

## Step 5 components

| Decision | Why |
|---|---|
| Countdown: `to`/`now` and `useCountdown` added | Not in `index.d.ts` (it takes `days`…`seconds`). With `to` (epoch ms) the countdown ticks itself, so only that leaf re-renders: at each minute boundary, then each second in the last hour (`nextTickDelay`). | Countdown parts as time runs down | Spec: "days, hours, minutes (seconds only in the last hour)". Days drop out under a day; in the last hour hours (always 00) drop out and seconds come in: DAYS HRS MIN → HRS MIN → MIN SEC. |
| Countdown is read in words without seconds | "Starts in: 3 days, 14 hours, 20 minutes" (sentence case, leading zero units dropped). Seconds are never spoken, so the `timer` label changes at most once a minute (spec). Under a minute: "less than a minute"; at zero: "now". |
| PredictionBar: `onPick` and `locked` added | Not in `index.d.ts`, which can only show a pick. | Ledger with no provider | Passes, charges, refunds and payouts are records with statuses; `provider` is `'none'` by check constraint and reads say `payments_connected: false`. Nothing moves money (owner decision pending; Step 8). Refunds are recorded `pending` and still come off the payout; closed payouts wait as `scheduled`; monthly renewals are recorded `due`. |
| Service fee is a placeholder in one place | `public.host_service_fee_policy()`: 8% of a payout week's gross charges, rounded to the nearest whole unit (matches −$36 on $456 in HostMembership). Every fee comes from `private.host_service_fee_cents()`. The Insights PNG's −$84 on $1,660 isn't consistent with any single rate, so seeded Insights show the computed fee instead. |
| Payout week | Friday 00:00 → next Friday 00:00 in the program's time zone, paid on that Friday (the designs' Friday payouts). The next payout is computed live; finished weeks are frozen by an hourly job. |
| Refund decisions | Host-only, audited with the previous membership state. Full or partial ends the membership now; KEEP IT stops renewal and keeps it to the period end (prototype copy). UNDO is allowed for 10 minutes while the refund is pending (matches core's join-decision undo window). `suggested_partial_cents` is the unused part of the period; the design's $25 is sample content. |
| Who pays what | Members are covered when the session's member price is 0; a pack is used at check-in when nothing else covers the person; otherwise a drop-in is due at the field until the host marks it paid. Hosts show HOST. |
| Automatic refunds | Driven by core's `host_session_log` (a `promoted` row naming the dropper) and by skipping a session, so every path that frees a spot refunds the same way. |
| League results are final | CONFIRM RESULT inserts an insert-only row (like Step 5's results); the prototype's UNDO after confirming isn't offered. A wrong score before confirmation is fixed with DISPUTE (captains resend). Rows go only when the whole program/league is deleted (trigger allows cascades). |
| Season page is public | Standings, fixtures and confirmed results are readable by anyone signed in once a league is active ("Public standings, results and the final"); captains' raw scores, disputes and who's in are hosts (and the submitter / the player) only. |
| RESULT TO CONFIRM lists reported games | Only fixtures past kick-off with a captain's score or an open dispute; unreported games still count as a game in hand in the standings. |
| Referee suggestion | League people marked `can_referee`, not on either team, not playing or refereeing within 75 minutes; most past accepted games first ("has reffed twice"). |
| Notifications anchor on a session | `host_update` needs an object the person can see; refund and league notes anchor on the person's latest session in the program (core does the same). People who never came to a session aren't notified. |
| Seeded past payouts are frozen sample rows | The three past payouts carry the PNG totals ($386, $402, $344) as closed weeks; the charges behind the last 60 days are generated separately, so Insights' revenue is computed and doesn't sum to those rows. |
