# Ojoro Core Prototype Flows

## Flow A — Movement

1. Home shows “Football tonight?” as actionable intent.
2. User opens Down For.
3. User commits with I’M DOWN.
4. Plan Forming begins at 4/8.
5. User commitment raises the count.
6. Simulated friends join until 7/8.
7. NEED ONE MORE becomes prominent.
8. Pull In a Friend completes the threshold.
9. GAME ON locks time/place.
10. Activity Detail becomes canonical.
11. Activity moves to LIVE.
12. User finishes activity.
13. AFTER/Recap appears.
14. RUN IT BACK resets the plan for the next session.

## Flow B — Crew Chat to Activity

Crew Home → Chat prompt “Basketball tomorrow?” → MAKE THIS A GAME → shared availability → Plan Forming → confirmed Activity.

## Flow C — Challenge

Friend Profile → Challenge → Call-Out → ACCEPT or COUNTER → active progress → result → REMATCH.

## Flow D — Activation

Onboarding → sports / goals / availability → Home → first activity → recap → Passport entry.

## Flow E — Clan

Clan → rivalry → roster → Clash → result → recap. Detailed Clan administration remains Tier-B after the core prototype.

## Flow F — Ojoro Now

Home → Ojoro Now → no exact activity → latent demand → Create from Demand → Plan Forming.

## Prototype principle

The prototype is intentionally real navigation and state, not a collection of static mockups. It is allowed to use in-memory data until the first vertical production slice connects API/database/realtime.
