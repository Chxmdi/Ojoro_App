## Cross-screen states required

Every applicable screen must specify:
- loading;
- skeleton;
- empty;
- first-use education;
- success;
- validation error;
- server error;
- offline;
- reconnecting;
- stale data;
- permission denied;
- privacy-limited;
- blocked-user interaction;
- capacity/full;
- expired object;
- deleted/unavailable object;
- moderation-restricted;
- reduced-motion behavior;
- large-text behavior;
- screen-reader order;
- deep-link entry;
- notification entry;
- share entry.

## D0 prioritization

### Tier A — prototype-complete
Onboarding, Home, Down For, I’M DOWN, Plan Forming, Ojoro Now, Activity, Create, Friends, Crew, Chat-to-Plan, Challenge, Compete, Map, Live, Recap, Run It Back, Profile, Passport.

### Tier B — high-fidelity before engineering reaches feature
Clans, matches, tournament/season, goals, reputation, host surfaces, notifications, Places.

### Tier C — system-specification before implementation
Settings, support, admin edge cases, secondary integration screens.

D0 does **not** require 272 unrelated visual compositions. It requires a complete system in which reusable patterns and state models cover the entire inventory without unresolved UX behavior.
